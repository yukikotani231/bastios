# Running Linux programs

BastiOS runs unmodified Linux x86-64 programs next to its own. This page says how it loads them and which system calls it implements, and how each behaves. [Getting started](getting-started.md), section 4, shows how to run one, and `make compat` (see [test/compat/README.md](../test/compat/README.md)) measures how much ordinary Linux userland works: a suite of checks, BusyBox applets, Lua, QuickJS, sqlite, tcc and GNU make, and the Bastio compiler with Z3.

## Loading programs

User programs are linked at `USER_BASE` (0x8000000000) behind a small header (magic, memory size, entry), flattened to raw images, and embedded in the kernel with `include_bytes`.

The kernel also loads Linux x86-64 ELF executables: fixed-address executables whose segments lie in the user window, and PIEs, which it places at `USER_BASE`. A dynamically linked PIE names its interpreter (`PT_INTERP`): the kernel loads that too, high in the window just below where `mmap` starts, and starts it with `AT_BASE` pointing at it; the interpreter then links the program. The interpreter is the file at that path, or, for musl's `/lib/ld-musl-x86_64.so.1` when there is no such file, a copy of musl's `libc.so` built into the kernel image, so programs linked only against musl's libc run as they come (other shared libraries would have to be files). It starts them with the stack the Linux ABI promises (argc, argv, envp and the auxiliary vector). Every header field is untrusted, and the proof shows each read stays inside the file and each copied byte lands in the window below the stack.

## System calls

Such programs make Linux system calls with the `syscall` instruction (`src/linux.bastio`): `read` (the console, blocking, a file or a pipe), `write` and `writev` (the console, a file or a pipe), `pipe`, `pipe2` (a pipe holds 64 KiB, and a write of up to `PIPE_BUF` bytes goes in whole), `mknod`/`mknodat` for named pipes, as `mkfifo` makes them (a writer's `open` waits for a reader; a FIFO is a file of the file system with the FIFO type bits, so it is listed, renamed and removed like a file and kept on the disk across reboots; up to four can be open at once), and for character and block device nodes (root only; the node keeps its device number as its contents and `stat` reports it in `st_rdev`; opening one gives the device its number names: 1:3 `/dev/null`, 1:5 `/dev/zero`, 1:8 and 1:9 the random devices, 5:0 and 5:1 the console, and `ENXIO` for any other) and socket nodes, `dup`, `dup2`, `dup3`, `fcntl` (duplicating, close-on-exec, record and open file description locks, leases, which are kept and reported but never broken, and a description's owner with `F_SETOWN`, `F_SETOWN_EX` and `F_SETSIG`: with `O_ASYNC` set, data arriving in a pipe or FIFO sends the owner SIGIO or the chosen signal, with the permissions of whoever set the owner; nothing else signals yet; `src/lxowner.bastio`), `flock` (`src/lxlock.bastio`; a conflicting lock waits, and a record-lock wait that would deadlock fails with `EDEADLK`), `poll` and `ppoll` (waiting until the console has a line, a pipe has data or room, a socket has data, a connection to accept or room to send, or the timeout passes; ppoll waits with its signal mask, as `rt_sigsuspend` does), `select` and `pselect6` (the same readiness over fd_sets; nothing is ever exceptional, the time left is not written back, and pselect6 waits with its signal mask), `eventfd` and `eventfd2` (with `EFD_SEMAPHORE`), `timerfd_create`, `timerfd_settime` and `timerfd_gettime` (realtime, monotonic and boot-time clocks, relative or absolute, once or periodic), `epoll_create`, `epoll_create1`, `epoll_ctl`, `epoll_wait`, `epoll_pwait` and `epoll_pwait2` (`src/lxevent.bastio`; readiness is what `poll` sees, so `EPOLLET` entries are reported level-triggered, `EPOLLONESHOT` holds, files cannot be watched as on Linux, an epoll instance inside another never reports ready, and the signal mask is not applied), `alarm`, `setitimer` and `getitimer` (`ITIMER_REAL` only, checked on each timer tick, so to within 10 ms), `pause`, `nanosleep` and `clock_nanosleep`, `clock_gettime`, `clock_getres`, `gettimeofday` and `time` (off the time-stamp counter, its rate measured at boot against the HPET, or the ACPI PM timer where there is no HPET; musl reads the monotonic and real-time clocks through the vDSO, with no system call; with no real-time clock, `CLOCK_REALTIME` counts from the epoch at boot), `open`, `openat` (with `O_EXCL` and `O_DIRECTORY`), `close`, `lseek` (from the start or the current offset), `unlink`, `unlinkat` (with `AT_REMOVEDIR` too), `mkdir`, `mkdirat`, `rmdir`, `rename`, `renameat` and `renameat2` (within one file system; a file or empty directory at the new name is replaced, by removing it first), `chdir`, `fchdir`, `chroot` (root only; absolute paths, absolute link targets and `..` at the top stay inside the new root, and `getcwd` shows paths from it), `faccessat`, `chmod`/`fchmod`/`fchmodat` and `utime`/`utimes`/`futimesat`/`utimensat` (each file keeps its permission bits and modification time, in memory and on the disk), `brk`, `mmap` (anonymous or a private copy of a file, anywhere or at a `MAP_FIXED` address; `MAP_SHARED` memory is shared with `fork`'s children, and a `MAP_SHARED` file mapping of a file opened for writing maps the page cache's pages (`src/pcache.bastio`; from a descriptor that may only read, it is a copy, which later writes to the file do not reach, and `mprotect` will not make it writable), so every process that maps the same part of a file shares it and `read`/`write` see the mapping's bytes; `msync`, `munmap` and exit write it back to the file), `munmap`, `mprotect` and `mremap` (unmapped pages fault, read-only pages fault on a write and stay read-only across `fork`, and `mremap` grows a mapping by moving its pages, down into the free space below it when it is the lowest mapping, so a buffer that keeps doubling takes no more address space than its size; the address space `munmap` frees is used again by later mappings; `src/lxmem.bastio`), `ioctl` (`FIONBIO`, `FIOCLEX` and `FIONCLEX` on any descriptor, `FIOASYNC` accepted though `SIGIO` is never sent for it; 

as `fcntl`'s `O_NONBLOCK` and `FD_CLOEXEC`; `TCGETS` and `TCSETS`/`TCSETSW`/`TCSETSF`, `TIOCGWINSZ`, `TIOCGPGRP` and `TIOCGSID` on the console, whose foreground group is always the caller's, as there is no job control; setting its group is accepted and ignored), signals (`rt_sigaction`, `rt_sigprocmask`, `rt_sigreturn`, `kill`, `tkill`, `tgkill`, `rt_sigpending`, `rt_sigtimedwait`, `rt_sigsuspend`, and `sigaltstack` (accepted, never used); SIGCHLD goes to a Linux parent when its child ends; a handler runs on the user stack in the frame Linux builds, default actions end the process or ignore the signal, Ctrl-C on the console sends SIGINT to the Linux programs on it, and a write to a pipe with no reader sends SIGPIPE; there is no stopping and there are no alternate signal stacks, and a siginfo carries the signal number and the sending process), `getuid` and friends (real, effective, saved and file-system user and group ids, changed by the `set` calls with Linux's rules; `src/lxcred.bastio`; what root alone may do is in [security.md](security.md)), `readv` (every buffer, on a file; into the first buffer with room otherwise), `pread64`, `pwrite64`, `ftruncate` and `truncate`, `uname` (Linux 6.1.0-bastios on x86_64), `getrlimit`/`prlimit64` (256 descriptors, the 64 KiB stack, the rest unlimited), `sysinfo`, `statfs`/`fstatfs`, `mount` and `umount2` (root's alone; tmpfs, and `bstdisk3`: a disk image made by `mkfs.bstdisk3`, given as an in-memory file or as the `/dev/loopN` bound to one (whose bytes cannot be read and which cannot be unbound while it is mounted: `EBUSY`), mounted as a second disk file system, one at a time; both on an empty in-memory directory, read-only with `MS_RDONLY`; `src/lxmount.bastio`), `getrusage`, `getrandom` (the bytes `/dev/urandom` gives: ChaCha20 keyed by a pool that takes the time-stamp counter on every scheduler pass, rekeyed after each block; the pool's entropy is estimated, not measured, and there is no hardware source yet), `getpriority`/`setpriority`, `umask`, `sched_yield`, `sched_getaffinity`, process groups and sessions (`setpgid`, `getpgid`, `setsid`, `getsid`; `kill` with 0 or a negative pid signals a group, and -1 every other Linux program), `chown`, `fchown`, `lchown` and `fchownat` (each file keeps its owner's user and group ids, in memory and on the disk, which keeps ids below 2^24), file permissions (`src/lxperm.bastio`: open, `execve`, `truncate` and `access` check a file's mode bits against the caller's ids, a path walk needs search permission on each directory, making and removing names needs write permission on the directory, a sticky directory such as `/tmp` or `/dev/shm` (where `sem_open` and `shm_open` make their files) keeps others' names, `chmod` and `utime` are for the owner, a new file belongs to its maker and takes the `umask`, and user 0 passes every check but may run only a file with an execute bit; supplementary groups count), `getcwd`, `stat`/`lstat`/`access`/`newfstatat`/`fstat` (`/`, `/bin` and the file system's directories are directories, `/bin/NAME` a built-in program, anything else a file; an open descriptor reports the console, a pipe, a directory or a file), `link` and `linkat` (hard links within one file system, not to directories; `st_nlink` counts a file's names), `symlink` and `symlinkat` (links in memory and on the disk, followed by every call that takes a path; `lstat`, `readlink`, `unlink`, `rename`, `mkdir` and `rmdir` act on a link itself), `readlink` and `readlinkat` (a link's target, and `/proc/PID/exe` and `/proc/PID/fd/N`; the console is `/dev/tty`, so `ttyname` works), a generated, read-only `/proc` (`mounts`, `meminfo`, `uptime`, `cpuinfo`, `filesystems`, the sysctls `kernel/tainted`, `pid_max` and `printk`, and per process `mounts`, `stat`, `status`, `cmdline` and `exe`, with `/proc/self`; enough for BusyBox's `ps`, `free`, `df` and `uptime`), `getdents64` (listing `/`, `/bin`, `/proc` and any directory of the file system; paths are taken from the working directory, with `.` and `..`, and the `*at` calls start relative paths at their directory descriptor), sockets over the kernel's UDP and TCP (`socket` for `AF_INET` datagrams and streams, `bind`, `listen`, `accept`, `accept4`, `connect`, `sendto`/`send`/`write`, `recvfrom`/`recv`/`read`, blocking or nonblocking (`SOCK_NONBLOCK`, `O_NONBLOCK` set with `fcntl` or `ioctl(FIONBIO)`, or `MSG_DONTWAIT` on a receive; a full connection then gives `EAGAIN`), `sendfile` from a file to a TCP connection, `getsockname`, `getpeername`; `AF_INET6` sockets reach IPv6 peers (`src/net6.bastio` translates their packets to and from the IPv4 stack, standing each peer in with an address in 240.0.0.0/8) as well as `::1` and `::ffff:a.b.c.d`, though `getsockname` reports our own address as `::ffff:a.b.c.d`; the kernel writes `/etc/resolv.conf` from the name server DHCP names, or 10.0.2.3 with the static address, so the C library's resolver works; `setsockopt` and `shutdown` are accepted and ignored, and closing a stream sends its FIN), `fork`, `vfork` and `clone(SIGCHLD)` (the window is copied, except the read-only pages of built-in programs, which every process running the program shares; descriptors are shared), `clone(CLONE_VM | CLONE_VFORK)` as `posix_spawn` makes it (the parent lends its address space to the child, and waits, until the child calls `execve` or ends), threads: `clone(CLONE_THREAD)` as `pthread_create` makes it (with `CLONE_SETTLS`, `CLONE_PARENT_SETTID`, `CLONE_CHILD_SETTID` and `CLONE_CHILD_CLEARTID`), `futex` (`WAIT`, `WAKE`, `REQUEUE`, `CMP_REQUEUE` and the bitset forms, with timeouts on the monotonic or, with `FUTEX_CLOCK_REALTIME`, the wall clock; within a process, and across processes for a futex in a `MAP_SHARED` page without `FUTEX_PRIVATE_FLAG`) and `set_tid_address`, so musl's mutexes, condition variables and joins work (`src/lxthread.bastio`; the threads of a process share its address space, descriptors, working directory and signal actions, and run on several processors at once (see "Threads on several processors" in [architecture.md](architecture.md)); `exit` from a thread ends that thread, `exit_group` the process), `execve` (built-in programs at `/bin/NAME`, a program from a file system reading its largest code segment's pages from the file when it first runs them (`src/lazy.bastio`; the kernel gives `EFAULT` for such a page passed to a system call before then), with `/bin/sh` being BusyBox's `ash` so `system` and `popen` get a POSIX shell, ELF files such as `/elfdemo` from memory or `disk/`, and `/proc/PID/exe`, the program that process runs, which is how ash runs a script with no `#!` line; a file starting with `#!` runs the interpreter that line names, with the line's argument, if any, and the script's path before the rest of argv, as on Linux: `ENOEXEC` for a line naming no interpreter, `ENOENT` for a missing one; with argv and the environment, up to 8192 arguments, 1024 environment strings and 128 KiB of them, laid out at the top of the stack as Linux does; a program the kernel itself starts, such as the shell's `ash`, gets `PATH`, `HOME=/` and `TERM=vt100`), `wait4`, `waitid` (ended children only), `times`, `gettid`, `arch_prctl(ARCH_SET_FS)` (the thread pointer), `set_tid_address`, `exit`, `exit_group`, `getpid` and `getppid`; `set_robust_list`, `rseq` and `clone3` fail with `-ENOSYS` quietly (glibc carries on without them, so static glibc programs such as Z3 run); every other call prints a note on the console and returns `-ENOSYS`. Linux fds 0 to 2 are the console, a terminal that starts in canonical mode: the kernel echoes what is typed, handles Backspace, hands a read the line once Enter (or Ctrl-D) is pressed, and turns LF into CR LF on output. A program can change that with `tcsetattr`, as editors and REPLs do: with `ICANON` off a read gets each byte as it is typed (`VMIN` above 1 counts as 1; with `VMIN` 0 it waits at most `VTIME` tenths of a second, or not at all), and `ECHO`, `ISIG` (Ctrl-C sends SIGINT), `ICRNL` and `OPOST`/`ONLCR` are obeyed; the other settings are kept and reported but change nothing. Pseudo-terminals (`src/lxpty.bastio`) give programs the same line discipline between two descriptors: opening `/dev/ptmx` makes a pair (four at a time) and returns its master end, `TIOCGPTN` and `TIOCSPTLCK` (`ptsname`, `unlockpt`) lead to the slave `/dev/pts/N`, and what the master writes is the slave's input, cooked as the settings say, while what the slave writes comes out of the master. Each pair keeps its own `termios`, window size (`TIOCSWINSZ` sends SIGWINCH to the foreground group), foreground group (`TIOCSPGRP`; Ctrl-C and Ctrl-\\ go to it) and session (`TIOCSCTTY`; `/dev/tty` opens the session's pty). Closing the last master sends SIGHUP to the session, after which slave reads find end of file and writes fail with `EIO`; a master read fails with `EIO` once every slave is closed. Dropbear's SSH server uses them for logins (`test/compat/ssh.txt`). `/dev/dsp` is the Open Sound System's playback device on an HD Audio card (`src/lxsnd.bastio`): it plays 48 kHz 16-bit stereo only, and the ioctls that set the rate, channels or format answer with that, as OSS allows; without a card it fails to open with `ENODEV` (see "Sound" in [architecture.md](architecture.md)). `/dev/input/mice` and `/dev/psaux` give the mouse's 3-byte packets (a PS/2 mouse's, or a USB mouse's turned into that form) (buttons with the sign bits, then x, then y, up positive), as Linux's mousedev does in its default mode: a read takes what is queued, waits when nothing is (or fails with `EAGAIN` if opened `O_NONBLOCK`; `fcntl` cannot change that later), and `poll` reports `POLLIN` when a packet is waiting. Writes, such as the ImPS/2 wheel setup, are swallowed without the answers Linux would give, so programs see a 3-button mouse without a wheel. Without a mouse the open fails with `ENODEV`. Each process has 256 descriptors (`src/lxfd.bastio`; more give `EMFILE`, and more than 1024 open file descriptions in all give `ENFILE`); each is the console or an open file description shared by `dup` and `fork`: a file in the file system below, one end of a pipe, a directory being listed, or a socket (`src/lxsock.bastio` and `src/lxtcp.bastio`, over the kernel's sockets in `src/net.bastio` and `src/tcp.bastio`). That is enough for C programs built against musl libc as static PIEs (`user/mhello.c`, `user/mtest.c`) to use `printf`, `malloc`, `fopen` and `fgets`, and for BusyBox's `ash`, built unmodified, to run as an interactive shell on the console and start other programs, with pipes and redirection. BusyBox's `ls`, `cat`, `wc`, `head`, `rm`, `cp`, `kill`, `sleep`, `mkdir`, `rmdir`, `pwd`, `mv`, `chmod`, `touch`, `stat`, `ln`, `readlink`, `mkfifo`, `mount`, `umount`, `truncate`, `chown`, and for users `su`, `login`, `passwd`, `chpasswd`, `adduser`, `addgroup`, `deluser`, `delgroup`, `id` and `whoami` (see [security.md](security.md)) are built in too, and `/bin/NAME` for each of them starts the BusyBox binary, which picks the applet from `argv[0]`. Each process has its own x87/SSE state, saved in a page of its own whenever it stops running. `int 0x80` keeps the BastiOS ABI, the one in bastiolang's user prelude. Calls 0 to 10 have named builtins there; the file calls (11 to 24, listed in `src/syscall.bastio`) go through its generic `sys_call` / `sys_send` / `sys_recv`, which lend the kernel a byte buffer.

A `poll`, `select`, `epoll_wait`, `pause`, `rt_sigsuspend`, `nanosleep` or `clock_nanosleep` that has to wait sleeps until a network frame comes in, the clock ticks (every 10 ms) or a signal is posted, and then looks again (`wait_asleep` in `src/lxtime.bastio`). So readiness that comes from elsewhere, such as a pipe another process writes, is seen up to 10 ms late, and a timeout ends up to 10 ms late. These calls used to run again on every pass of the scheduler, which kept a processor busy for every waiting process: an idle nginx kept two busy, and a 16 MiB download from it went at 0.86 MB/s, against 7 MB/s now (QEMU TCG, two processors).

Calls newer kernels added, and some they replaced (`src/lxextra.bastio`, `src/lxpidfd.bastio`): `preadv2` and `pwritev2` (at an offset, or at -1 for the file offset; `RWF_HIPRI`, `RWF_DSYNC`, `RWF_SYNC` and `RWF_NOWAIT` are accepted and change nothing, `RWF_APPEND` and other flags are `EOPNOTSUPP`), the old `getdents` beside `getdents64` (both list `.` and `..` first, and `lseek` on a directory with `SEEK_SET` or `SEEK_CUR` moves through the listing, so `rewinddir`, `telldir` and `seekdir` work), `sysfs` and `ustat` (the four file system types `/proc/filesystems` names), `fchmodat2` (with `AT_SYMLINK_NOFOLLOW`, which fails with `EOPNOTSUPP` on a link as on Linux, and `AT_EMPTY_PATH`), `readahead` and `sync_file_range` (checked, then nothing to do: there is no read-ahead or write-back to start), `vhangup` (root only; there is no terminal to hang up), `execveat` (with `AT_EMPTY_PATH` to run an open file; `AT_SYMLINK_NOFOLLOW` on a link is `ELOOP`), `O_PATH` (a handle that only names a file: calls that would read, write or change it fail with `EBADF`), the process descriptors `pidfd_open`, `pidfd_send_signal` (with or without a siginfo), `pidfd_getfd`, `poll` on a pidfd (readable once the process has ended) and `waitid(P_PIDFD)`, and `kcmp`, `process_vm_readv` and `process_vm_writev` (a pidfd keeps naming its process after the slot is reused by another; `PIDFD_THREAD` is not there, and `kcmp` compares open file descriptions exactly but every other resource per thread group). Who may reach another process this way is in [security.md](security.md). `inotify_init`, `inotify_init1`, `inotify_add_watch` and `inotify_rm_watch` (`src/lxinotify.bastio`) watch files and directories: reading the descriptor gives Linux's `struct inotify_event` records, in Linux's order (a directory hears of its entries' events, with their names, before the entry itself; renames tie `IN_MOVED_FROM` and `IN_MOVED_TO` with a cookie; equal events in a row are one; a full queue ends with `IN_Q_OVERFLOW`), and `poll` and `epoll` see it readable while events wait. Events come from the Linux system calls (not from BastiOS's own, nor from writes through shared mappings); there is no `IN_UNMOUNT`; `IN_DELETE_SELF` comes when the last name goes rather than when the last open descriptor closes, so an unlinked file still open reports only to watches on itself; there are at most 8 instances of 16 watches and 31 queued events each, as `/proc/sys/fs/inotify` says.
