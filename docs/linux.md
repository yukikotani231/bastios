# Running Linux programs

BastiOS runs unmodified Linux x86-64 programs next to its own. This page says how it loads them and which system calls it implements, and how each behaves. [Getting started](getting-started.md), section 4, shows how to run one, and `make compat` (see [test/compat/README.md](../test/compat/README.md)) measures how much ordinary Linux userland works: a suite of checks, BusyBox applets, Lua, QuickJS, sqlite, tcc and GNU make, and the Bastio compiler with Z3.

## Loading programs

User programs are linked at `USER_BASE` (0x8000000000) behind a small header (magic, memory size, entry), flattened to raw images, and embedded in the kernel with `include_bytes`.

The kernel also loads Linux x86-64 ELF executables: fixed-address executables whose segments lie in the user window, and PIEs, which it places at `USER_BASE`. A dynamically linked PIE names its interpreter (`PT_INTERP`): the kernel loads that too, high in the window just below where `mmap` starts, and starts it with `AT_BASE` pointing at it; the interpreter then links the program. The interpreter is the file at that path, or, for musl's `/lib/ld-musl-x86_64.so.1` when there is no such file, a copy of musl's `libc.so` built into the kernel image, so programs linked only against musl's libc run as they come (other shared libraries would have to be files). It starts them with the stack the Linux ABI promises (argc, argv, envp and the auxiliary vector). Every header field is untrusted, and the proof shows each read stays inside the file and each copied byte lands in the window below the stack.

## System calls

Such programs make Linux system calls with the `syscall` instruction (`src/linux.bastio`): `read` (the console, blocking, a file or a pipe), `write` and `writev` (the console, a file or a pipe), `pipe`, `pipe2` (a pipe holds 64 KiB, and a write of up to `PIPE_BUF` bytes goes in whole), `mknod`/`mknodat` for named pipes, as `mkfifo` makes them (a writer's `open` waits for a reader; a FIFO is a file of the file system with the FIFO type bits, so it is listed, renamed and removed like a file and kept on the disk across reboots; up to four can be open at once), `dup`, `dup2`, `dup3`, `fcntl` (duplicating, close-on-exec, and record and open file description locks), `flock` (`src/lxlock.bastio`; a conflicting lock waits, and a record-lock wait that would deadlock fails with `EDEADLK`), `poll` and `ppoll` (waiting until the console has a line, a pipe has data or room, a socket has data, a connection to accept or room to send, or the timeout passes; ppoll waits with its signal mask, as `rt_sigsuspend` does), `select` and `pselect6` (the same readiness over fd_sets; nothing is ever exceptional, the time left is not written back, and pselect6 waits with its signal mask), `eventfd` and `eventfd2` (with `EFD_SEMAPHORE`), `timerfd_create`, `timerfd_settime` and `timerfd_gettime` (realtime, monotonic and boot-time clocks, relative or absolute, once or periodic), `epoll_create`, `epoll_create1`, `epoll_ctl`, `epoll_wait`, `epoll_pwait` and `epoll_pwait2` (`src/lxevent.bastio`; readiness is what `poll` sees, so `EPOLLET` entries are reported level-triggered, `EPOLLONESHOT` holds, files cannot be watched as on Linux, an epoll instance inside another never reports ready, and the signal mask is not applied), `alarm`, `setitimer` and `getitimer` (`ITIMER_REAL` only, checked on each timer tick, so to within 10 ms), `pause`, `nanosleep` and `clock_nanosleep`, `clock_gettime`, `clock_getres`, `gettimeofday` and `time` (off the time-stamp counter, its rate measured at boot against the HPET, or the ACPI PM timer where there is no HPET; musl reads the monotonic and real-time clocks through the vDSO, with no system call; with no real-time clock, `CLOCK_REALTIME` counts from the epoch at boot), `open`, `openat` (with `O_EXCL` and `O_DIRECTORY`), `close`, `lseek` (from the start or the current offset), `unlink`, `unlinkat` (with `AT_REMOVEDIR` too), `mkdir`, `mkdirat`, `rmdir`, `rename`, `renameat` and `renameat2` (within one file system; a file or empty directory at the new name is replaced, by removing it first), `chdir`, `fchdir`, `faccessat`, `chmod`/`fchmod`/`fchmodat` and `utime`/`utimes`/`futimesat`/`utimensat` (each file keeps its permission bits and modification time, in memory and on the disk), `brk`, `mmap` (anonymous or a private copy of a file, anywhere or at a `MAP_FIXED` address; `MAP_SHARED` memory is shared with `fork`'s children, and a `MAP_SHARED` file mapping maps the page cache's pages (`src/pcache.bastio`), so every process that maps the same part of a file shares it and `read`/`write` see the mapping's bytes; `msync`, `munmap` and exit write it back to the file), `munmap`, `mprotect` and `mremap` (unmapped pages fault, read-only pages fault on a write and stay read-only across `fork`, and `mremap` grows a mapping by moving its pages; `src/lxmem.bastio`), `ioctl` (`TCGETS` and `TCSETS`/`TCSETSW`/`TCSETSF`, `TIOCGWINSZ`, `TIOCGPGRP` and `TIOCGSID` on the console, whose foreground group is always the caller's, as there is no job control; setting its group is accepted and ignored), signals (`rt_sigaction`, `rt_sigprocmask`, `rt_sigreturn`, `kill`, `tkill`, `tgkill`, `rt_sigpending`, `rt_sigtimedwait`, `rt_sigsuspend`, and `sigaltstack` (accepted, never used); SIGCHLD goes to a Linux parent when its child ends; a handler runs on the user stack in the frame Linux builds, default actions end the process or ignore the signal, Ctrl-C on the console sends SIGINT to the Linux programs on it, and a write to a pipe with no reader sends SIGPIPE; there is no stopping and there are no alternate signal stacks, and a siginfo carries the signal number and the sending process), `getuid` and friends (real, effective, saved and file-system user and group ids, changed by the `set` calls with Linux's rules; `src/lxcred.bastio`), `readv` (every buffer, on a file; into the first buffer with room otherwise), `pread64`, `pwrite64`, `ftruncate` and `truncate`, `uname` (Linux 6.1.0-bastios on x86_64), `getrlimit`/`prlimit64` (16 descriptors, the 64 KiB stack, the rest unlimited), `sysinfo`, `statfs`/`fstatfs`, `mount` and `umount2` (tmpfs, and `bstdisk3`: a disk image made by `mkfs.bstdisk3`, given as an in-memory file, mounted as a second disk file system, one at a time; both on an empty in-memory directory, read-only with `MS_RDONLY`; `src/lxmount.bastio`), `getrusage`, `getrandom` (the bytes `/dev/urandom` gives: ChaCha20 keyed by a pool that takes the time-stamp counter on every scheduler pass, rekeyed after each block; the pool's entropy is estimated, not measured, and there is no hardware source yet), `getpriority`/`setpriority`, `umask`, `sched_yield`, `sched_getaffinity`, process groups and sessions (`setpgid`, `getpgid`, `setsid`, `getsid`; `kill` with 0 or a negative pid signals a group, and -1 every other Linux program), `chown`, `fchown`, `lchown` and `fchownat` (each file keeps its owner's user and group ids, in memory and on the disk, which keeps ids below 2^24), file permissions (`src/lxperm.bastio`: open, `execve`, `truncate` and `access` check a file's mode bits against the caller's ids, a path walk needs search permission on each directory, making and removing names needs write permission on the directory, a sticky directory such as `/tmp` keeps others' names, `chmod` and `utime` are for the owner, a new file belongs to its maker and takes the `umask`, and user 0 passes every check but may run only a file with an execute bit; there are no supplementary groups), `getcwd`, `stat`/`lstat`/`access`/`newfstatat`/`fstat` (`/`, `/bin` and the file system's directories are directories, `/bin/NAME` a built-in program, anything else a file; an open descriptor reports the console, a pipe, a directory or a file), `link` and `linkat` (hard links within one file system, not to directories; `st_nlink` counts a file's names), `symlink` and `symlinkat` (links in memory and on the disk, followed by every call that takes a path; `lstat`, `readlink`, `unlink`, `rename`, `mkdir` and `rmdir` act on a link itself), `readlink` and `readlinkat` (a link's target, and `/proc/PID/exe` and `/proc/PID/fd/N`; the console is `/dev/tty`, so `ttyname` works), a generated, read-only `/proc` (`mounts`, `meminfo`, `uptime`, `cpuinfo`, `filesystems`, the sysctls `kernel/tainted`, `pid_max` and `printk`, and per process `mounts`, `stat`, `status`, `cmdline` and `exe`, with `/proc/self`; enough for BusyBox's `ps`, `free`, `df` and `uptime`), `getdents64` (listing `/`, `/bin`, `/proc` and any directory of the file system; paths are taken from the working directory, with `.` and `..`, and the `*at` calls start relative paths at their directory descriptor), sockets over the kernel's UDP and TCP (`socket` for `AF_INET` datagrams and streams, `bind`, `listen`, `accept`, `accept4`, `connect`, `sendto`/`send`/`write`, `recvfrom`/`recv`/`read`, blocking or with `SOCK_NONBLOCK`/`MSG_DONTWAIT`, `getsockname`, `getpeername`; `AF_INET6` sockets reach IPv6 peers (`src/net6.bastio` translates their packets to and from the IPv4 stack, standing each peer in with an address in 240.0.0.0/8) as well as `::1` and `::ffff:a.b.c.d`, though `getsockname` reports our own address as `::ffff:a.b.c.d`; the kernel writes `/etc/resolv.conf` from the name server DHCP names, or 10.0.2.3 with the static address, so the C library's resolver works; `setsockopt` and `shutdown` are accepted and ignored, and closing a stream sends its FIN), `fork`, `vfork` and `clone(SIGCHLD)` (the whole window is copied, and descriptors are shared), `clone(CLONE_VM | CLONE_VFORK)` as `posix_spawn` makes it (the parent lends its address space to the child, and waits, until the child calls `execve` or ends), threads: `clone(CLONE_THREAD)` as `pthread_create` makes it (with `CLONE_SETTLS`, `CLONE_PARENT_SETTID`, `CLONE_CHILD_SETTID` and `CLONE_CHILD_CLEARTID`), `futex` (`WAIT`, `WAKE`, `REQUEUE`, `CMP_REQUEUE` and the bitset forms, with timeouts on the monotonic or, with `FUTEX_CLOCK_REALTIME`, the wall clock; within a process, and across processes for a futex in a `MAP_SHARED` page without `FUTEX_PRIVATE_FLAG`) and `set_tid_address`, so musl's mutexes, condition variables and joins work (`src/lxthread.bastio`; the threads of a process share its address space, descriptors, working directory and signal actions, and run on several processors at once (see "Threads on several processors" in [architecture.md](architecture.md)); `exit` from a thread ends that thread, `exit_group` the process), `execve` (built-in programs at `/bin/NAME`, with `/bin/sh` being BusyBox's `ash` so `system` and `popen` get a POSIX shell, ELF files such as `/elfdemo` from memory or `disk/`, and `/proc/PID/exe`, the program that process runs, which is how ash runs a script with no `#!` line; with argv and the environment), `wait4`, `waitid` (ended children only), `times`, `gettid`, `arch_prctl(ARCH_SET_FS)` (the thread pointer), `set_tid_address`, `exit`, `exit_group`, `getpid` and `getppid`; `set_robust_list`, `rseq` and `clone3` fail with `-ENOSYS` quietly (glibc carries on without them, so static glibc programs such as Z3 run); every other call prints a note on the console and returns `-ENOSYS`. Linux fds 0 to 2 are the console, a terminal that starts in canonical mode: the kernel echoes what is typed, handles Backspace, hands a read the line once Enter (or Ctrl-D) is pressed, and turns LF into CR LF on output. A program can change that with `tcsetattr`, as editors and REPLs do: with `ICANON` off a read gets each byte as it is typed (`VMIN` above 1 counts as 1; with `VMIN` 0 it waits at most `VTIME` tenths of a second, or not at all), and `ECHO`, `ISIG` (Ctrl-C sends SIGINT), `ICRNL` and `OPOST`/`ONLCR` are obeyed; the other settings are kept and reported but change nothing. Each process has 16 descriptors (`src/lxfd.bastio`; more give `EMFILE`); each is the console or an open file description shared by `dup` and `fork`: a file in the file system below, one end of a pipe, a directory being listed, or a socket (`src/lxsock.bastio` and `src/lxtcp.bastio`, over the kernel's sockets in `src/net.bastio` and `src/tcp.bastio`). That is enough for C programs built against musl libc as static PIEs (`user/mhello.c`, `user/mtest.c`) to use `printf`, `malloc`, `fopen` and `fgets`, and for BusyBox's `ash`, built unmodified, to run as an interactive shell on the console and start other programs, with pipes and redirection. BusyBox's `ls`, `cat`, `wc`, `head`, `rm`, `cp`, `kill`, `sleep`, `mkdir`, `rmdir`, `pwd`, `mv`, `chmod`, `touch`, `stat`, `ln`, `readlink`, `mkfifo`, `mount`, `umount`, `truncate` and `chown` are built in too, and `/bin/NAME` for each of them starts the BusyBox binary, which picks the applet from `argv[0]`. Each process has its own x87/SSE state, saved in a page of its own whenever it stops running. `int 0x80` keeps the BastiOS ABI, the one in bastiolang's user prelude. Calls 0 to 10 have named builtins there; the file calls (11 to 24, listed in `src/syscall.bastio`) go through its generic `sys_call` / `sys_send` / `sys_recv`, which lend the kernel a byte buffer.
