# Proof coverage of the kernel

BastiOS is written in Bastio, where memory safety is proved at build time
and needs no annotations: ownership of pages, page tables and device
registers, bounds, overflow and division are checked in every function
whether or not it has a specification. A `requires` or `ensures` clause is
something more: it states what a function needs from its callers and what
it promises back, and the compiler proves each one. This page measures
where the kernel states such things and where it says nothing, and lists
what to specify next.

It is an audit of the source, not a claim about the proofs. Whether a
clause holds is decided by Z3 at build time; this page counts which
functions have clauses worth relying on. `tools/proof_coverage.py`
produces every table below from `src/` in a second, with no compiler and
no solver, so the numbers can be refreshed after any change:

```sh
tools/proof_coverage.py                  # totals
tools/proof_coverage.py --markdown       # the tables on this page
tools/proof_coverage.py --list lxmem     # every function of one file, with its tier
```

## What the tiers mean

Each function falls into one tier, by its strongest clause.

| Tier | Meaning | Example |
|---|---|---|
| functional | an `ensures` that describes the result or the changed state: a range, a set of possible values, a relation to the arguments | `lx_munmap` returns 0, `-EINVAL` or the disk-retry marker |
| frame | `ensures` only that the kernel is still well formed (`kok(k)`, `mem_ok(m)`, a page table keeps its level, a buffer keeps its length) | most system-call handlers |
| requires | a `requires` clause only: callers must prove it, but learn nothing back | a getter that reads a table slot |
| none | no clause | a table of constants |

"Frame" is not a defect by itself. A page-table walker has nothing to say
about its result beyond handing every page back, and for those the frame
clause is the whole specification. It is a gap when the function returns a
count, an address or `-errno` that the caller then uses: the caller
proves nothing about it, so either the function is trusted to return
something sensible or each caller clamps the value again. The system-call
handlers are the largest group of that kind.

What the tiers do not measure: the contents of pages (the proof tracks who
owns each page, not what is in it), termination, and whether a clause
that exists is the *right* one. A function can sit in the functional tier
with a weak clause such as `result <= 255`.

## Reading the results

- Most of the kernel's functions are `Kernel`-threading helpers whose
  frame clause (`kok(k)`) is the right specification. The tiers that matter
  are the `u64`-returning handlers and the helpers that turn a program's
  arguments into table indexes.
- **Memory management** is the best covered area: the page-table and
  user-copy layer (`space`, `usermem`, `pages`) states ranges and counts
  for what it returns (`copy_to_user` never reports more than it was
  given, `user_range` implies the whole range is inside the window,
  `win_range` implies a page-aligned address below the stack). Until this
  audit the system calls on top of it (`mmap`, `mremap`, `brk`, `munmap`,
  `mprotect`, `msync`, `mincore`, `madvise`) promised only that the kernel
  stayed well formed. They now also state what they may return: `-errno`
  or an address inside the user window for the calls that hand out memory,
  and a fixed set of results for the others.
- **System-call arguments** is the largest gap. Pipe, eventfd and pty reads
  and writes and regular-file reads now state that they never report more bytes than were asked
  for (`lx_count_or_fail`); the other handlers, from `lx_write_fd` and
  `lx_getdents` to `linux_syscall` itself, still say only `kok(k)`. The
  calls that install a descriptor (`dup`, `dup2`, `F_DUPFD`, eventfd) say
  they return a descriptor below `LXNFD` or `-errno`. The
  user-pointer boundary is already tight, because every handler reaches
  user memory through `copy_from_user` and `copy_to_user`; the missing
  piece is the same statement one level up, for what each handler returns.
- **Device drivers**: the receive-buffer address handed to the card is now
  bounded (at or below 4 GiB plus one buffer, the limit the legacy queues
  take). What stays outside every proof is what the hardware does with
  the addresses it is given (see [trusted-base.md](trusted-base.md)).

## What to specify next, in order

1. **Byte counts of the remaining read and write paths** (`lx_write_fd`,
   `ev_read`, `lx_sendto`, `lx_recvmsg`, `lx_getdents`, `dev_read`,
   `proc_read`, `loop_io`): each leaf gets
   `lx_count_or_fail(result, n)`, and then the dispatcher can state it for
   every file kind at once.
2. **The other descriptor- and pid-returning calls** (`open`, `socket`,
   `accept`, `pipe`, `fork`, `clone`, `wait4`): result is `-errno` or a
   value below the table size, so that no caller needs to re-check it
   before indexing.
3. **Getters that feed an index** (`pgid_of`, `sid_of`, `row_file`,
   `vpid_of`, `pidarg_k`): they read a table the proof knows nothing about,
   so callers clamp the result. The process table needs an invariant (for
   example every pid word is below `NPROC`) before these can promise it.
4. **`linux_syscall`**: one clause saying the result handed back to the
   program is `-errno` or a count within the call's own bound, once the
   handlers below it state theirs.
5. **Constant tables with no clause** (`sct_default`, `dev_rdev`,
   `rdev_dev`, the sysctl defaults): low risk, but a one-line range makes
   the consumers' proofs shorter.
6. **Hardware-facing code that cannot be specified**: register values read
   from a device are unknown to the proof by design. Those functions stay
   in the none and requires tiers, and the trusted base page says why.

Each item is a mechanical change: add the clause, build, and let Z3 say
whether the body already satisfies it. Where it does not, the
counterexample points at a real unchecked path.
