# X11 programs

BastiOS has no X server of its own, but Linux's runs on it: Alpine's Xvfb (an X server that draws into memory) and X clients such as xterm work unmodified, and `bx11` puts the X screen in a `bwm` window.

- Xvfb is started with `-fbdir DIR`, which keeps the screen in the file `DIR/Xvfb_screen0` (24 bit depth: `-screen 0 640x480x24`), and `-ac`, which needs no X authority.
- `bx11 [-f FILE] [-s SOCKET] [-t TITLE]` (`user/bx11.c`) opens a `bwm` window the size of the X screen and copies the rows of `FILE` that changed into it twenty times a second. The keys and pointer events `bwm` sends it go to the X server through the XTEST extension, so the server needs no input device. The cursor keys, Home, End, Page Up and Page Down, Delete, Ctrl with a letter, Tab and Shift-Tab are mapped; the keyboard is the server's US map.
- X clients connect to the server's socket, `/tmp/.X11-unix/X0`, with `DISPLAY=:0`.

The clipboard goes both ways. `bx11` keeps a small window of its own on the X server, offers the text in `/tmp/bwm.clip` (what a `bterm` window selected, or the editor cut) as the CLIPBOARD and PRIMARY selections (UTF8_STRING or STRING, up to 60000 bytes), and, when an X client takes either selection, asks for its text and writes it to `/tmp/bwm.clip`, so a copy in an X program pastes in `bterm` or `bfiles` and the other way round. The last one to copy wins. It hears of new selection owners through the XFIXES extension; without it the clipboard is not shared (and `bx11` says so). `test/bx11_clip_test.sh` checks it with the real `bx11`, Xvfb and `xclip` on the host.

`x11start` (`test/compat/x11/x11start.sh`) does all of it: `x11start -r /alpine -g 800x600 xterm` mounts `/dev` and `/proc` in the Alpine root, starts Xvfb there, opens the `bwm` window with `bx11` (from `/disk/bx11` unless `-b` says otherwise) and runs the program, and everything ends with the program. `-c` names a second root for the client, `-d` the display number. Run it from a terminal window (or `bwm -c`) while `bwm` is running. It needs a BusyBox with `mount` and `chroot` (`BB`, default `/disk/busybox`).

`test/compat/x11.txt` does this in the compatibility suite with the Xvfb and xterm of two Alpine images, entered with `chroot`, and a stand-in for `bwm` that types into the window (`make compat`, lane `x11`). A GTK 3 program, PuTTY (the `jlesage/putty` image), is a third case: it starts and draws its window on the X screen. A Qt 5 program, MediaInfo (`jlesage/mediainfo`), is a fourth, and a larger one, KeePassXC (`jlesage/keepassxc`), a fifth. A Java 8 Swing program, the installer of JDownloader (`jlesage/jdownloader-2`), is a sixth, and a wxWidgets one, Audacity (`jlesage/audacity`), a seventh, and a Python program with PyQt 5, dupeGuru (`jlesage/dupeguru`), an eighth, and puddletag (`jlesage/puddletag`), another Python and PyQt 5 program, a ninth, and QDirStat (`jlesage/qdirstat`), a Qt 5 disk usage viewer, a tenth, and FileZilla (`jlesage/filezilla`), a GTK 3 FTP client, an eleventh, and Avidemux (`jlesage/avidemux`), a Qt 5 video editor, a twelfth, and HandBrake (`jlesage/handbrake`), a GTK 3 video transcoder, a thirteenth, and MKVToolNix (`jlesage/mkvtoolnix`), a Qt 5 Matroska tool, a fourteenth, and Czkawka (`jlesage/czkawka`), a GTK 4 duplicate finder written in Rust, a fifteenth, and tsMuxeR (`jlesage/tsmuxer`), a Qt 5 transport stream muxer, a sixteenth, and FileBot (`jlesage/filebot`), a Java media renamer, a seventeenth, and FreeFileSync (`jlesage/freefilesync`), a GTK folder synchroniser, an eighteenth, and Krusader (`jlesage/krusader`), a Qt file manager, a nineteenth, and Evince (`jess/evince`), a GTK PDF viewer, a twentieth, and VLC (`jess/vlc`), a media player, a twenty-first. VLC refuses to run as root, so the case starts it through `su` as `nobody`. Its image links `/etc/passwd` to `/tmp/.passwd`, which the image's own init writes at start, so the case writes a one-line `root` entry there.

A BastiOS disk holds at most 262144 entries (files, directories and links), and the roots above nearly fill the first X11 disk, so later apps go on a second one (`x11disk.py --part2`, `test/compat/x11b.txt`, lane `x11b`) that holds the server and client roots again and one root per app. GIMP (`jess/gimp`), an image editor, is its first case; its icon theme, time zone database and message catalogues are left out of the root to save entries. LibreOffice (`jess/libreoffice`), an office suite, is the second: the case starts Writer.

Not done yet: the window cannot be resized (the X screen has one size), the X windows are all inside the one `bwm` window (there is no X window manager, so xterm gets the focus from the pointer's position), and `bx11` is not in the kernel image: it comes from a disk. Wayland is not tried.
