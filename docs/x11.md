# X11 programs

BastiOS has no X server of its own, but Linux's runs on it: Alpine's Xvfb (an X server that draws into memory) and X clients such as xterm work unmodified, and `bx11` puts the X screen in a `bwm` window.

- Xvfb is started with `-fbdir DIR`, which keeps the screen in the file `DIR/Xvfb_screen0` (24 bit depth: `-screen 0 640x480x24`), and `-ac`, which needs no X authority.
- `bx11 [-f FILE] [-s SOCKET] [-t TITLE]` (`user/bx11.c`) opens a `bwm` window the size of the X screen and copies the rows of `FILE` that changed into it twenty times a second. The keys and pointer events `bwm` sends it go to the X server through the XTEST extension, so the server needs no input device. The cursor keys, Home, End, Page Up and Page Down, Delete, Ctrl with a letter, Tab and Shift-Tab are mapped; the keyboard is the server's US map.
- X clients connect to the server's socket, `/tmp/.X11-unix/X0`, with `DISPLAY=:0`.

`test/compat/x11.txt` does this in the compatibility suite with the Xvfb and xterm of two Alpine images, entered with `chroot`, and a stand-in for `bwm` that types into the window (`make compat`, lane `x11`).

Not done yet: the window cannot be resized (the X screen has one size), there is no clipboard between X and `bterm`, the X windows are all inside the one `bwm` window (there is no X window manager, so xterm gets the focus from the pointer's position), and `bx11` is not in the kernel image: it comes from a disk. Wayland is not tried.
